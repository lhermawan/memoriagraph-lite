Architecture & Reference Map

MemoriaGraph Lite — App Map

A complete architectural overview tracing how problem-solving episodes become an interactive knowledge graph and reusable AI memory.

1. System Overview

MemoriaGraph Lite is an autonomous cognitive memory engine built around the Cognitive Triad: Problem ➔ Mitigation ➔ Solution. It eliminates AI agent amnesia without loading context windows with raw conversational noise.

2. Reference Code Route

Trace a memory from MCP ingestion down to database edge derivation and live canvas rendering:

Stop 1: MCP Tool Ingestion Handler

mcp_server.py ➔ handle_tools_call()

Receives stdio JSON-RPC requests from AI agents (Claude Code, Cursor). Validates mandatory triad fields (title, problem, mitigation, solution) and delegates persistence to database.add_episode().

Stop 2: SQLite Schema & Graph Derivation

database.py ➔ add_episode() & get_graph()

Persists the episode into SQLite table episodes, automatically derives directed graph edges (HAS_PROBLEM, MITIGATED_BY, SOLVED_BY, TAGGED_WITH), and outputs Vis-Network formatted JSON.

Stop 3: Interactive Physics Canvas & Node Inspector

static/app.js ➔ handleNodeSelect() & filterGraph()

Renders nodes with distinct glow colors, handles camera focus, controls physics dampening, and slides out the detailed triad inspector drawer upon user click.

3. "To Change This, Start Here"

Modify Node Colors & Theme static/style.css & static/app.js (options.groups)

Adjust hex colors, glow shadows, or node sizing for problems, mitigations, and solutions.

Add New MCP Agent Tools mcp_server.py (TOOLS list)

Add new tool definitions and handle their arguments inside handle_tools_call().

Adjust Graph Relationship Logic database.py (add_episode)

Change how directional edges are linked between episodes, tags, and cognitive entities.

Customize Default Sample Cases sample_data.py (SAMPLE_EPISODES)

Update or extend the preloaded troubleshooting scenarios seeded by the demo button.

4. A Practice to Reuse

Thin Verifiable Slices with Automated Assert Scripts

Instead of building all database, API, and frontend layers in bulk before testing, the build was divided into 4 self-verifying slices (test_slice1.py, test_slice2.py, test_slice3.py). Each slice proved a complete runnable behavior immediately upon completion. This ensured zero broken builds and eliminated debugging regressions.
